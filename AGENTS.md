# Product Captures contributor instructions

When changing C#, .NET project files or build configuration, first read and apply the complete [C#/.NET standard](docs/standards/csharp-dotnet.md). Its rules and examples are self-contained; source links are optional further reading. Closer project instructions take precedence. Review behavior, structure, style and evidence separately. Formatting or helper extraction alone is not a readable refactor: identify the dense expression, mixed responsibility or hidden lifetime being improved. Use the official `csharp-refactoring` skill when available for structural cleanup; the standard also works without it. Keep useful operations explicit without adding frameworks or dependencies.

Preserve public JSON/API/defaults/errors, rendering string values, output ownership, explicit screenshot reuse, publication guards and process cancellation/cleanup. Keep the Node adapter and approved image bytes unchanged during readability work. Verify all three project format checks/builds, core/adapter contracts, host contracts, composition parity and a fresh generic browser smoke before release. Release names are exactly their version tags.
